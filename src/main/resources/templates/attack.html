⚔️ Attack Lab

This page hosts a simulated malicious page inside a sandboxed, srcdoc iframe with no allow-same-origin permission. When it submits its hidden form, your browser sends the request with Origin: null — exactly what happens when a real attacker's site (e.g. evil-example.com) tricks your browser into POSTing to this app while you're logged in.

Current mode:
Defense Mode: CSRF token, Origin/Referer, and (for JSON endpoints) custom-header checks are all enforced. The attack below should be blocked and logged as suspicious.
Attack Mode: server-side CSRF checks are bypassed, and cookies are reissued with SameSite=None to simulate an app that never adopted SameSite cookies. The attack below should succeed.

Simulated malicious page

Pretend this iframe is http://evil-example.com/free-prize.html. It contains a hidden form auto-targeting this app's /transfer endpoint for $500 to account attacker, with no CSRF token.

Want to see this from a genuinely different origin instead of a sandboxed iframe? A standalone copy of this malicious page ships in this project's malicious-site/index.html — open it via a different port (e.g. python3 -m http.server 9000 in that folder) while this app runs on :8080, and it will attempt the exact same attack cross-origin.
